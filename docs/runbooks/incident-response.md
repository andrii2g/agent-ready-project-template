# Incident Response Runbook

1. Protect people, data, devices, and production availability.
2. Record the incident start time, reporter, symptoms, and affected scope.
3. Contain the issue using the least destructive reversible action.
4. Preserve relevant logs and evidence without exposing secret or personal data.
5. Identify the failure mode and validate the recovery plan.
6. Restore service or safe operation and monitor.
7. Communicate through approved channels.
8. Complete a blameless review with corrective actions and owners.

Do not allow an agent to execute destructive containment or disclose incident
details without explicit authorization.
