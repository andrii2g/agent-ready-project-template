# Write an ADR

1. Confirm the decision is durable and costly enough to record.
2. Copy `docs/adr/0000-template.md` to the next sequential number.
3. Describe the context and decision forces without rewriting project history.
4. State the decision precisely.
5. Record positive, negative, security, operational, and migration consequences.
6. Document meaningful alternatives and why they were rejected.
7. Define validation and review conditions.
8. Link the ADR from `PROJECT.md` or architecture documentation when relevant.

Do not mark an ADR Accepted unless the responsible human or governance process
has accepted it.
